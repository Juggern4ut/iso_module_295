12 - Formulare II & Validierung

Eingaben prüfen und sauber verarbeiten

Lernziele dieser Lektion

  • Erklären können, wieso Eingaben immer auf dem Server validiert werden müssen
  • Pflichtfelder, Zahlen, E-Mail-Adressen und Auswahlen mit trim(), filter_var() und in_array() prüfen können
  • Fehlermeldungen in einem Array sammeln und beim passenden Feld anzeigen können
  • Die Validierung in eine Funktion auslagern können
  • Mit Post/Redirect/Get und einer Flash-Meldung doppeltes Absenden verhindern können
Rückblick

Was kann schiefgehen?

Unser Bestellformular aus Lektion 11 nimmt alles an, was geschickt wird:

Leer

Bestellung ohne Namen

Unsinn

Menge -5 ergibt ein negatives Total

Doppelt

F5 nach dem Absenden bestellt nochmals

Heute: Eingaben validieren, Fehler verständlich anzeigen und doppeltes Absenden verhindern

Clientseitig

Validierung im Browser

HTML kann schon vieles prüfen, bevor das Formular abgeschickt wird:

                    
                        <input type="text"   name="name"  required maxlength="50">
                        <input type="email"  name="email" required>
                        <input type="number" name="menge" min="1" max="20">
                        <input type="text"   name="plz"   pattern="[0-9]{4}">

Vorteil: Der Benutzer erhält sofort eine Rückmeldung, ohne dass ein Request zum Server geht

Sicherheit

Reicht das nicht?

Clientseitig (HTML / JS)

  • schnelle Rückmeldung
  • lässt sich in den DevTools entfernen
  • wird umgangen, wenn man Requests direkt schickt

Serverseitig (PHP)

  • kann nicht umgangen werden
  • einzige Prüfung, auf die man sich verlassen kann
  • erst nach dem Absenden
                    
                        curl -d "name=&menge=-5" http://localhost/shop/index.php

Clientseitig ist Komfort, serverseitig ist Pflicht - in PHP wird immer validiert

Grundlagen

Ablauf der Validierung

1. Einlesen
Werte aus $_POST holen und mit trim() aufbereiten
→
2. Prüfen
jede Regel testen, Fehler in einem Array $errors sammeln
→
3. Entscheiden
keine Fehler → verarbeiten
sonst → Formular mit Meldungen

Alle Fehler auf einmal sammeln, nicht beim ersten abbrechen - so kann der Benutzer alles in einem Durchgang korrigieren

Grundlagen

Fehler sammeln

                    
                        <?php
                        $errors = [];
                        $name = trim($_POST["name"] ?? "");

                        if ($name === "") {
                            $errors["name"] = "Bitte geben Sie einen Namen ein.";
                        } elseif (mb_strlen($name) > 50) {
                            $errors["name"] = "Der Name darf höchstens 50 Zeichen lang sein.";
                        }

                        if (count($errors) === 0) {
                            // Bestellung speichern
                        }

Feldname als Schlüssel → Meldung beim richtigen Feld. mb_strlen() zählt Umlaute korrekt

Quiz

Was gibt dieser Code aus?

                    
                        <?php
                        $anzahlKinder = "0"; // aus einem Formular

                        if (empty($anzahlKinder)) {
                            echo "Pflichtfeld!";
                        } else {
                            echo "OK";
                        }

Pflichtfeld! - empty() hält auch "0" für leer. Für Pflichtfelder darum trim($wert) === "" verwenden

Prüfen

filter_var()

Prüft, ob ein String ein gültiger Wert eines bestimmten Typs ist - und gibt ihn umgewandelt zurück, sonst false

AufrufErgebnis
filter_var("42", FILTER_VALIDATE_INT)42 (int)
filter_var("12.5", FILTER_VALIDATE_INT)false
filter_var("12.5", FILTER_VALIDATE_FLOAT)12.5 (float)
filter_var("anna@example.ch", FILTER_VALIDATE_EMAIL)"anna@example.ch"
filter_var("anna@example", FILTER_VALIDATE_EMAIL)false
Prüfen

Zahlen mit Bereich prüfen

                    
                        <?php
                        $menge = filter_var($_POST["menge"] ?? "", FILTER_VALIDATE_INT, [
                            "options" => ["min_range" => 1, "max_range" => 20],
                        ]);

                        if ($menge === false) {
                            $errors["menge"] = "Die Menge muss zwischen 1 und 20 liegen.";
                        }

                        $email = filter_var($_POST["email"] ?? "", FILTER_VALIDATE_EMAIL);
                        if ($email === false) {
                            $errors["email"] = "Bitte geben Sie eine gültige E-Mail-Adresse ein.";
                        }

Im Gegensatz zu (int) wird "abc" nicht still zu 0 - ungültige Werte werden erkannt

Quiz

Was gibt dieser Code aus?

                    
                        <?php
                        $anzahl = "0"; // aus einem Formular

                        if (!filter_var($anzahl, FILTER_VALIDATE_INT)) {
                            echo "Ungültig";
                        } else {
                            echo "OK";
                        }

Ungültig - die Zahl 0 ist gültig, aber !0 ergibt true. Darum immer mit === false prüfen

Prüfen

Auswahlen prüfen

                    
                        <?php
                        $lieferung = $_POST["lieferung"] ?? "";
                        if (!in_array($lieferung, ["abholen", "post"], true)) {
                            $errors["lieferung"] = "Bitte wählen Sie eine Lieferart.";
                        }

                        $produktId = filter_var($_POST["produkt"] ?? "", FILTER_VALIDATE_INT);
                        if ($produktId === false || !isset($produkte[$produktId])) {
                            $errors["produkt"] = "Bitte wählen Sie ein Produkt.";
                        }

Select, Radio und Checkbox lassen sich in den DevTools ändern - nur Werte aus einer Whitelist akzeptieren. Pflicht-Checkbox: isset($_POST["agb"])

Prüfen

Muster prüfen mit preg_match()

                    
                        <?php
                        $plz = trim($_POST["plz"] ?? "");
                        if (preg_match('/^[0-9]{4}$/', $plz) !== 1) {
                            $errors["plz"] = "Die PLZ besteht aus 4 Ziffern.";
                        }
/ ... /Anfang und Ende des Musters (regulärer Ausdruck)
^ / $Anfang / Ende des Strings - sonst würde auch "x80001" passen
[0-9]{4}genau 4 Zeichen von 0 bis 9

preg_match() gibt 1 zurück, wenn das Muster passt, sonst 0

Anzeigen

Fehler beim Feld anzeigen

                    
                        <label for="email">E-Mail</label>
                        <input type="email" id="email" name="email" value="<?= e($email) ?>">

                        <?php if (isset($errors["email"])): ?>
                            <p class="fehler"><?= e($errors["email"]) ?></p>
                        <?php endif; ?>

Werte erhalten

Wie in Lektion 11: der Benutzer muss nur korrigieren, nicht alles neu eingeben

Klare Meldung

Sagen, was erwartet wird: "Die PLZ besteht aus 4 Ziffern" statt "Ungültige Eingabe"

Praxis

Validierung als Funktion

                    
                        <?php
                        function validiereBestellung(array $daten): array
                        {
                            $errors = [];
                            if (trim($daten["name"] ?? "") === "") {
                                $errors["name"] = "Bitte geben Sie einen Namen ein.";
                            }
                            if (filter_var($daten["email"] ?? "", FILTER_VALIDATE_EMAIL) === false) {
                                $errors["email"] = "Ungültige E-Mail-Adresse.";
                            }
                            return $errors;
                        }

                        $errors = validiereBestellung($_POST);

Ohne HTML und Session: einzeln testbar und in eine eigene Datei auslagerbar (require_once)

Problem

Doppelt abgeschickt

Was passiert?

Nach dem Absenden zeigt der Browser die Antwort auf einen POST-Request. F5 wiederholt genau diesen Request - inklusive aller Daten

Folge

Der Browser fragt "Erneut senden?" - wer bestätigt, bestellt ein zweites Mal

Ziel: Nach einer erfolgreichen Verarbeitung soll der Browser eine normale GET-Seite anzeigen

Praxis

Post / Redirect / Get

POST
Formular wird abgeschickt, PHP validiert und speichert
→
Redirect
PHP antwortet nur mit Location: index.php
→
GET
Browser lädt index.php neu - F5 ist jetzt harmlos 
                    
                        <?php
                        if (count($errors) === 0) {
                            $_SESSION["bestellungen"][] = $bestellung;
                            header("Location: index.php");
                            exit;
                        }

Nur bei Erfolg umleiten - bei Fehlern wird das Formular mit den Meldungen direkt angezeigt

Praxis

header() und exit

header("Location: ...")

Schickt dem Browser einen HTTP-Header mit der neuen Adresse. Wie session_start() muss er vor jeder Ausgabe stehen

exit;

header() beendet das Skript nicht. Ohne exit läuft der Rest weiter

Fehler Cannot modify header information - headers already sent: vor dem header() wurde schon etwas ausgegeben (HTML, echo, Leerzeichen vor <?php)

Praxis

Flash-Meldung

beim erfolgreichen POST

                    
                        <?php
                        $_SESSION["flash"] = "Danke!";
                        header("Location: index.php");
                        exit;

beim nächsten GET

                    
                        <?php
                        $flash = $_SESSION["flash"] ?? null;
                        unset($_SESSION["flash"]);
                        ?>
                        <?php if ($flash !== null): ?>
                            <p><?= e($flash) ?></p>
                        <?php endif; ?>

Nach dem Redirect sind alle Variablen weg - die Meldung nimmt den Umweg über die Session (Lektion 07) und erscheint genau einmal

Quiz

Wo bleibt die Meldung?

                    
                        <?php
                        session_start();
                        if ($_SERVER["REQUEST_METHOD"] === "POST") {
                            $_SESSION["flash"] = "Anmeldung gespeichert";
                            header("Location: index.php");
                        }
                        $flash = $_SESSION["flash"] ?? null;
                        unset($_SESSION["flash"]);
                        ?>
                        <?php if ($flash !== null): ?>
                            <p><?= e($flash) ?></p>
                        <?php endif; ?>

exit fehlt: Das Skript läuft im POST-Request weiter und löscht die Meldung, bevor der Browser die Seite per GET neu lädt

Achtung

Typische Fehler

Nur im Browser validiert

required und min ersetzen keine Prüfung in PHP

!filter_var(...)

Gültige 0 wird als Fehler erkannt → === false

exit vergessen

Nach header("Location: ...") läuft das Skript weiter

Ausgabe vor header()

headers already sent → Logik oben, HTML unten

TL;DR

  • Validierung im Browser ist Komfort - in PHP wird immer validiert
  • Fehler in $errors["feld"] sammeln und beim Feld anzeigen, Eingaben erhalten
  • trim($x) === "" für Pflichtfelder, filter_var() mit === false für Zahlen und E-Mail, in_array() für Auswahlen
  • Nach erfolgreichem POST: header("Location: ...") + exit (Post/Redirect/Get)
  • Erfolgsmeldungen als Flash-Meldung über die Session - nächste Lektion: Dateien & Sessions
