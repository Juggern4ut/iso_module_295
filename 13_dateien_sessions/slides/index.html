13 - Dateien & Sessions

Daten dauerhaft speichern und Bereiche schützen

Lernziele dieser Lektion

  • Erklären können, wann Daten in die Session und wann in eine Datei gehören

  • Einen Datei-Upload mit $_FILES entgegennehmen, prüfen und sicher speichern können
  • Ein Login mit password_hash(), password_verify() und Sessions umsetzen und Seiten damit schützen können

Dateien

Dateien lesen und schreiben

                    
                        <?php
                        file_put_contents("notiz.txt", "Brot ist ausverkauft");

                        if (file_exists("notiz.txt")) {
                            echo file_get_contents("notiz.txt");
                        }

                        file_put_contents("notiz.txt", "\nKäse ist da", FILE_APPEND);
file_put_contents()schreibt einen String in eine Datei - erstellt oder überschreibt sie
file_get_contents()liest die ganze Datei als String
FILE_APPENDhängt den String am Ende an, statt zu überschreiben
Dateien

Pfade mit __DIR__

                    
                        <?php
                        // __DIR__ = Ordner, in dem DIESE PHP-Datei liegt
                        $datei = __DIR__ . "/data/zaehler.txt";

                        $anzahl = file_exists($datei) ? (int) file_get_contents($datei) : 0;
                        file_put_contents($datei, $anzahl + 1);

Relative Pfade

"data/x.txt" hängt davon ab, welches Skript gerade läuft - in eingebundenen Dateien geht das schnell schief

Ordner muss existieren

file_put_contents() erstellt Dateien, aber keine Ordner. Den Ordner data/ vorher anlegen

Quiz

Was gibt dieser Code aus?

                    
                        <?php
                        file_put_contents("log.txt", "A");
                        file_put_contents("log.txt", "B", FILE_APPEND);
                        file_put_contents("log.txt", "C");

                        echo file_get_contents("log.txt");

C - ohne FILE_APPEND wird die Datei vollständig überschrieben, AB ist danach weg

JSON

Arrays als JSON speichern

PHP

                    
                        <?php
                        $anmeldungen = [
                            ["vorname" => "Anna", "kurs" => "brot"],
                            ["vorname" => "Jürg", "kurs" => "kaese"],
                        ];
                        $json = json_encode($anmeldungen,
                            JSON_PRETTY_PRINT
                            | JSON_UNESCAPED_UNICODE);
                        file_put_contents("data.json", $json);

data.json

                    
                        [
                          {
                            "vorname": "Anna",
                            "kurs": "brot"
                          },
                          {
                            "vorname": "Jürg",
                            "kurs": "kaese"
                          }
                        ]

In eine Datei passen nur Strings · JSON_PRETTY_PRINT: lesbar eingerückt · JSON_UNESCAPED_UNICODE: "Jürg" statt "J\u00fcrg"

JSON

JSON wieder laden

                    
                        <?php
                        $json = file_get_contents("anmeldungen.json");
                        $anmeldungen = json_decode($json, true);

                        echo $anmeldungen[1]["vorname"]; // Jürg

Der zweite Parameter true macht aus JSON-Objekten assoziative Arrays - genau so, wie wir sie gespeichert haben

JSON ist auch das Format, in dem Webapplikationen Daten mit JavaScript (fetch()) austauschen

Quiz

Was passiert hier?

                    
                        <?php
                        $json = '{"name": "Anna", "kurs": "brot"}';
                        $anmeldung = json_decode($json);

                        echo $anmeldung["name"];

Fatal Error Cannot use object of type stdClass as array - ohne true liefert json_decode() ein Objekt statt eines Arrays

Praxis

Laden als Funktion

                    
                        <?php
                        function ladeJson(string $datei): array
                        {
                            $pfad = __DIR__ . "/data/" . $datei;
                            if (!file_exists($pfad)) {
                                return [];
                            }
                            return json_decode(file_get_contents($pfad), true) ?? [];
                        }

Beim allerersten Aufruf gibt es die Datei noch nicht - dann starten wir mit einem leeren Array. ?? [] fängt eine kaputte Datei ab (json_decode() gibt dann null zurück)

Praxis

Speichern als Funktion

                    
                        <?php
                        function speichereJson(string $datei, array $daten): void
                        {
                            $json = json_encode($daten, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
                            file_put_contents(__DIR__ . "/data/" . $datei, $json);
                        }

                        $anmeldungen = ladeJson("anmeldungen.json");
                        $anmeldungen[] = $daten;
                        speichereJson("anmeldungen.json", $anmeldungen);

Upload

Dateien hochladen

                    
                        <form method="post" enctype="multipart/form-data">
                            <input type="file" name="bild" accept="image/jpeg, image/png">
                            <button>Hochladen</button>
                        </form>

enctype

Ohne multipart/form-data schickt der Browser nur den Dateinamen, nicht die Datei

method="post"

Dateien passen nicht in die URL - Uploads gehen nur per POST

Upload

Was kommt in PHP an?

Hochgeladene Dateien landen nicht in $_POST, sondern in $_FILES["bild"]:

SchlüsselInhaltBeispiel
nameOriginalname auf dem PCzopf.jpg
tmp_nametemporäre Datei auf dem ServerC:\xampp\tmp\php3A1.tmp
sizeGrösse in Bytes248311
errorFehlercode, 0 = OKUPLOAD_ERR_OK
typeTyp laut Browserimage/jpeg

Die temporäre Datei wird am Ende des Requests gelöscht - wir müssen sie vorher verschieben

Upload

Upload prüfen

                    
                        <?php
                        $bild = $_FILES["bild"] ?? null;
                        $erlaubt = ["image/jpeg" => "jpg", "image/png" => "png"];

                        if ($bild === null || $bild["error"] !== UPLOAD_ERR_OK) {
                            $errors["bild"] = "Bitte wählen Sie ein Bild aus.";
                        } elseif ($bild["size"] > 2 * 1024 * 1024) {
                            $errors["bild"] = "Das Bild darf höchstens 2 MB gross sein.";
                        } elseif (!isset($erlaubt[mime_content_type($bild["tmp_name"])])) {
                            $errors["bild"] = "Nur JPG- und PNG-Bilder sind erlaubt.";
                        }

mime_content_type() liest den Typ aus dem Inhalt der Datei, z.B. "image/png" · 2 MB = 2 × 1024 × 1024 Bytes

Upload

Upload speichern

                    
                        <?php
                        if (count($errors) === 0) {
                            $name = basename($bild["name"]);
                            move_uploaded_file($bild["tmp_name"], __DIR__ . "/bilder/" . $name);
                        }
basename()nur der Dateiname, z.B. zopf.jpg - ohne Pfadangaben wie ../
move_uploaded_file()verschiebt die temporäre Datei an ihren Platz

Den Namen (zopf.jpg) merken wir uns in einer JSON-Datei, damit wir das Bild später anzeigen können

Sicherheit

Wieso so umständlich?

type nicht vertrauen

$_FILES["bild"]["type"] schickt der Browser - das lässt sich fälschen. mime_content_type() schaut sich den Inhalt der Datei an

name absichern

Der Name kann ../ enthalten und die Datei so ausserhalb von bilder/ ablegen. basename() behält nur den Dateinamen. Gleicher Name → altes Bild wird überschrieben

Schlimmster Fall: Jemand lädt hack.php hoch und ruft /bilder/hack.php auf - der Server führt seinen Code aus

Sessions

Sessions sind auch Dateien

Wo legt PHP die Daten aus $_SESSION ab? Standardmässig in einer Datei pro Session: 

                    
                        C:\xampp\tmp\sess_8f3ac9d2e1b47a0c5d6e...
                    
                
                    
                        benutzer|s:5:"admin";flash|s:6:"Danke!";

Der Dateiname enthält die Session-ID aus dem Cookie PHPSESSID (Lektion 07). PHP liest die Datei bei session_start() und schreibt sie am Ende des Skripts zurück

Login

Passwörter speichern

Für ein Login brauchen wir Benutzer mit Passwort - aber nie das Passwort selbst speichern: 

                    
                        <?php
                        $hash = password_hash("sonnenhof", PASSWORD_DEFAULT);
                        // $2y$10$XJmpNx0LuLKYrboKhv9UheieSQjx22VrMeFmaC/bk4fNLP2zPOGzC

                        if (password_verify($eingabe, $hash)) {
                            echo "Passwort stimmt";
                        }

Ein Hash lässt sich nicht zurückrechnen. Wird benutzer.json gestohlen, sind die Passwörter trotzdem nicht bekannt

Quiz

Was gibt dieser Code aus?

                    
                        <?php
                        $a = password_hash("sonnenhof", PASSWORD_DEFAULT);
                        $b = password_hash("sonnenhof", PASSWORD_DEFAULT);

                        var_dump($a === $b);
                        var_dump(password_verify("sonnenhof", $b));

bool(false) und bool(true) - jeder Hash enthält ein zufälliges Salt. Darum nie mit === vergleichen, sondern immer mit password_verify()

Login

Login mit Formular

                    
                        <?php
                        $benutzer = ladeJson("benutzer.json"); // ["admin" => "$2y$10$..."]
                        $name = $_POST["benutzername"] ?? "";
                        $hash = $benutzer[$name] ?? null;

                        if ($hash !== null && password_verify($_POST["passwort"] ?? "", $hash)) {
                            session_regenerate_id(true);
                            $_SESSION["benutzer"] = $name;
                            header("Location: admin.php");
                            exit;
                        }
                        $fehler = "Benutzername oder Passwort ist falsch.";

session_regenerate_id(true): neue Session-ID nach dem Login (Session-Fixation, Lektion 07). Nur eine Fehlermeldung: nicht verraten, ob es den Benutzer gibt

Login

Seiten schützen

auth.php

                    
                        <?php
                        if (!isset($_SESSION["benutzer"])) {
                            header("Location: login.php");
                            exit;
                        }

admin.php

                    
                        <?php
                        require_once "app.php";
                        require_once "auth.php";
                        // ab hier nur noch eingeloggt

Die Prüfung steht einmal in auth.php - jede geschützte Seite bindet sie als Erstes ein

Einen Link auszublenden schützt nichts: Wer die URL admin.php kennt, ruft sie direkt auf. Ohne exit läuft die Seite trotz Umleitung weiter

Login

Logout

                    
                        <?php
                        // logout.php
                        session_start();
                        unset($_SESSION["benutzer"]);
                        session_regenerate_id(true);

                        header("Location: index.php");
                        exit;

Mit unset() bleiben andere Werte wie eine Flash-Meldung erhalten. Soll alles weg, geht auch session_destroy() (Lektion 07)

Achtung

Typische Fehler

json_decode($json)

true vergessen → Objekt statt Array

FILE_APPEND vergessen

Datei wird bei jedem Aufruf überschrieben

enctype fehlt

$_FILES bleibt leer

Passwort im Klartext

Immer password_hash() und password_verify()

TL;DR

  • Session = Daten eines Besuchers, Datei = Daten der Applikation für alle
  • file_put_contents() / file_get_contents() mit Pfaden über __DIR__; Arrays mit json_encode() / json_decode($json, true)
  • Upload: enctype, $_FILES, Fehler, Grösse und Typ prüfen, mit basename() und move_uploaded_file() speichern
  • Login: password_verify(), session_regenerate_id(true), geschützte Seiten über auth.php
